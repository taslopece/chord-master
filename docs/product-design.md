# Chord Master 产品设计

## 产品定位

Chord Master 是一组面向和弦学习与听感训练的轻量音乐工具。产品强调三个原则：

1. 每个工具都可以独立打开和使用。
2. 不同工具共享一致的音乐理论、音频与视觉系统。
3. 保持纯静态、可离线、可直接部署到 GitHub Pages。

产品不应把所有能力不断堆叠到单个页面。查阅、训练和未来可能出现的练习工具具有不同的用户目标，应当分别拥有独立入口和页面。

## 信息架构

```text
产品主页 index.html
├── 和弦图鉴 chord-atlas.html
├── 听辨训练 ear-training.html
└── 未来工具
    ├── 音程训练
    ├── 和弦进行训练
    └── 指板训练
```

- 产品主页负责介绍产品及展示工具入口。
- 工具页可以从主页进入，也可以通过独立 URL 直接访问、收藏和分享。
- 工具之间不要求按固定流程使用。

## 技术架构

项目继续采用无后端的多页面静态网站：

```text
index.html
chord-atlas.html
ear-training.html
assets/
├── css/common.css
├── js/music-theory.js
├── js/audio-engine.js
├── js/chord-atlas.js
├── js/ear-training.js
└── audio/
docs/
```

公共模块职责：

- `common.css`：全站视觉变量、布局、按钮与导航。
- `music-theory.js`：音名、调式、和弦公式及音高计算。
- `audio-engine.js`：采样加载、变调、播放、停止和播放序列。
- 各工具脚本只处理自身页面状态与交互。

在功能规模尚小时不引入框架或构建步骤。只有当页面数量、共享状态或测试需求明显增加时，再评估模块打包方案。

## 视觉与交互原则

- 保持深色、清晰、以黄和青色区分根音与其他构成音的视觉语言。
- 一级导航始终明确当前所在工具，并提供返回产品主页的路径。
- 每个页面只突出一个主要任务，避免让查阅和测试状态互相干扰。
- 桌面端与移动端都应可用，宽内容允许横向滚动但不能破坏主要操作。
- 音频播放必须由用户主动触发，并始终提供明确的停止方式和播放状态。

## 音频与版权原则

- 优先使用 CC0 或明确允许商业使用与再分发的音源。
- 所有第三方音频都必须在 `THIRD_PARTY_AUDIO_LICENSES.md` 中记录来源、许可证、文件和获取日期。
- 项目总大小控制在 1 GB 内，任何单个文件不得超过 100 MB。
- 实际目标应远低于上限；音频按工具或乐器延迟加载。
- 第一版允许使用少量基准采样配合小范围变调，后续再根据听感增加采样密度与演奏法。

## 开发顺序

1. 将现有单页重构为产品主页、和弦图鉴和听辨训练三个页面。
2. 抽取公共样式、音乐理论和音频播放模块。
3. 保证和弦图鉴功能在迁移前后等价。
4. 实现听辨训练的最小可用版本。
5. 增加速度、循环、播放高亮和训练统计。
6. 再开发吉他指法及按具体指法播放。

## 文档维护规则

- 产品范围或页面关系改变时，更新本文档。
- 单个工具的交互、规则或路线变化时，更新对应功能文档。
- 已确定的产品决策应先写入文档或与实现同时写入，避免只保留在聊天上下文中。
- 文档描述目标和约束；当前实现状态应明确标注，不能把规划写成已完成功能。
